# TOPWAVE 与其他 Amazon US 商品标准上架 SOP

版本 1.0 · 2026-11-12 · 中文协作 / 美式英语销售内容。

目标：由实物与证据出发，形成消费者定位、准确图像、可追溯关键词和可直接使用的上架内容。适用于 TOPWAVE 及后续其他品牌、品类；新 SKU 重新核验事实。本文是操作文档，执行入口为同目录上层 `SKILL.md`。

## 0. 建档与项目状态

建立项目编号、品牌、SKU/变体、Amazon US 产品类型、负责人、已有资料和目标交付。恢复已有任务先读事实和决策，不重做已确认步骤。

建议按实际项目保存：原图/标签/规格证据、事实表、竞品表、图片版本、ABA 原文件及词表、最终文案、发布检查、决策与未决事项。用文件名区分 SKU、渠道、版本和日期。

每项结论注明来源和状态：

- **用户确认**：用户/工厂提供的书面规格，注明时间与原话定位。
- **图片可见**：仅描述可观察外观，保留图名和局部位置。
- **研究证据**：ASIN/页面/原始评论等，注明访问日期与变体。
- **分析判断**：消费者画像、风格、机会推论，注明依据。
- **待核验/冲突**：缺证据或相互矛盾，标出影响范围。

这些状态不是可靠性评分；工厂标签与用户口述冲突也要核对，不能机械地任选一个。

## 1. 第一阶段：商品理解、市场与消费者定位

### 1.1 图像事实核验

识别图片属于自有实物、竞品还是风格参考。观察轮廓、比例、配色/花型、纹理、结构、正反面、包边/接缝、标签、配件和拍摄环境。把“看到什么”与“可能是什么”分开。

不得仅凭图认定棉/羊毛/聚酯百分比、织物工艺、洗护、重量、尺寸、认证、耐用/抗菌/阻燃/不掉毛性能。影棚的沙发、豪宅、摆件只是拍摄构图；需要消费者与用途证据才能形成场景建议。

### 1.2 主动询问

按当前阻塞程度每轮问 3–5 项，已有资料不再问：

1. 这张图是自己的商品、竞品还是风格图？品牌、SKU、计划售卖哪些变体？
2. 实测尺寸/单位、公差、重量、材质成分、工艺、洗标、包装与随货配件？有对应照片/规格单吗？
3. 主要使用人群/场景、希望突出什么、已知限制和退货原因？这些是目标还是已有客户反馈？
4. Amazon US 产品类型、售价/试售价、FBA/FBM、成本和可用促销预算？不涉及定价时不强求成本。
5. 有参考 ASIN/原图使用权吗？有品牌备案/A+权限、认证或检测报告、已有评论和 ABA 文件吗？

材料或洗护缺失时仍可研究场景、构图和竞品；相应承诺留空。不要把待确认字段藏进看似最终的英文文案。

### 1.3 竞品与市场调研

用消费者会用的品类词检索 Amazon US，结合用户竞品选取约 5–10 个可比商品（内部建议，随任务规模调整）。区分自然位/广告位；记录配送地区和时间，避免把个性化页面当全站固定排名。

记录 ASIN、产品 URL、原始主图/副图链接或截图来源、对应变体、尺寸/材料/件数、售价与 coupon 条件、评论数/星级、核心卖点、A+信息结构和差评顾虑。抓不到就标“未核实”，不编 ASIN、销量或评论。

竞品评价若用于判断问题，记录样本范围/日期、原文定位和主题频次；不能用几条评价声称全市场比例。竞品宣称也只是竞品页面信息，不是我们的检测证据。第三方销量或流量单独列估算来源/日期，不冒称 Amazon 官方。

用证据回答：美国消费者称它什么、为何购买、在哪使用、最在意什么、与相邻品类的差别、愿意接受的价位和容易误解之处。输出 1 个主要定位及必要的次级场景，画像只写可支持的部分，不硬编年龄/收入/住宅类型。

如需定价，结合尺寸/材料/件数、到手价、履约成本和促销空间给区间及假设，不仅抄最低价格。

**阶段交付**：事实表 + 竞品原图与数据表 + 消费者定位 + 3–5 个可证明卖点 + 购买顾虑/退货风险 + 待确认事项。

**进入图片制作条件**：已明确售卖商品与参考图角色；关键视觉细节有实物依据。关键材料/尺寸未证实，不制作带这些承诺的画面。

## 2. 第二阶段：主图、副图、A+ 与促销素材

### 2.1 图片计划

先定义每张图帮助买家完成哪个判断，数量按实际后台与预算确定。典型组合是主图、使用场景、结构/纹理、尺寸与比例、关键差异、已证实护理/使用方法、包装/清单；“6 图加视频”是建议，不是每个 SKU 的硬性门槛。

对每张素材注明：渠道、信息任务、画面构图、实物参考、不可变细节、允许调整项、英文标题/说明、声明证据、技术规格、状态。A+ 使用当前可用模块及其桌面/移动端尺寸，不把某个固定画布套给所有模块。

### 2.2 主图

按最新类目规则处理真实产品照片。通用基线为纯白背景、商品完整清晰、正确数量/颜色/比例、约占 85% 画面；无叠加宣传字、徽章、水印和误导性道具。实物已有 logo 与后加 logo 区分；随货配件或包装怎样展示查类目要求。

白底抠图、光线和构图调整后仍要核对真实性。不把纯生成商品效果图直接标为正式合规主图；没有足够实物照片时先做概念/补拍简报。主图验收通过也不能保证平台审核通过。

### 2.3 副图、A+、促销

副图使用可信比例和美国生活场景。尺寸以真实商品换算 inch/cm，避免用小沙发/小人物制造超大错觉。道具不得暗示随货；必要时在合适位置说明。

A+ 讲用途、细节、选购和限制；图片 alt text 准确描述内容，不能拿无关词堆砌。比较表只列同品牌真实在售/可用商品及已核实属性；没有其他商品时改做单品特征模块，不能编造同品牌 SKU 或“Others”竞品栏。促销价格/时限只用于允许的渠道和活动，不写进常驻主图或 A+。

### 2.4 生成、检查和迭代

制作前实际查看原图。提示词分为：商品锚点、场景/构图、光线、允许调整、禁止改变、输出规格。以原图编辑尽量保存身份；工具无法保留关键细节就改用实物合成/重拍。

逐图检查：

- 商品外形、长宽比、渐变方向、颜色面积、纹理密度、包边、接缝、正反面、logo/洗标和数量。
- 是否新添了图案、附件、虚构包装、不同材质、夸张厚度或错误尺度。
- 尺寸、材料、洗护、认证与文案能否逐项指向证据；英文拼写、数字和移动端字号是否清楚。
- 技术规格、白底、裁切、内容版权及适用 AI 人物披露要求。

每轮只修改需要调整的项，保留原图、上一版、修改说明和当前选版。用户指出细节错误时先修正商品事实，再同步涉及的所有图片和文案。

**阶段交付**：图片规划表、可预览图片、可编辑文件（工具支持时）、最终导出、修改记录。只有制作简报时明确还没有最终图。

## 3. 第三阶段：真实 ABA、可追溯词表与文案

### 3.1 请求数据与边界

请求用户提供 Amazon US Brand Analytics → Search Terms 的真实 CSV/XLSX，并说明周期、站点、导出筛选词/ASIN及是否全量；优先近期完整周期，季节性分析另外索要同季历史。SQP、广告 Search Term Report 与 ABA Search Terms 分开处理，不互换字段定义。

原文件存在时直接使用；缺原文件先请求。没有真实 ABA 可继续做候选研究或文案草稿，但不得标为“基于 ABA 的最终关键词表”。Sif、MerchantWords 等只作独立辅助估算。

### 3.2 清洗与追溯

1. 原文件只读留档，记录文件名、SHA-256、站点、报告、周期和筛选范围。
2. 检查 BOM、编码、额外元数据行、字段映射、分隔符、引号内换行和空值。SFR 转整数后排序，不能按文本排序。
3. 原始 query 和原始 SFR 不覆盖；标准化字段另存。用原始逻辑记录号/工作表行号定位，有嵌入换行时不能随意称为物理文本行。
4. 仅在同站点/同报告/同周期内排序。重复或冲突数据记录处理原因；同 SFR 保留并列，不自动改名次或平均。
5. 原始全集和最终词表分开；最终相关词按 SFR 升序，缺 SFR 另列。相关性和字段分配为分析判断，不伪装成 ABA 原始列。

SFR 小表示相对更热；不能换算绝对月搜索量。缺词可能源于导出筛选、周期、拼写、截断等，不等于零搜索。点击/转化份额仅在原报告真实提供且口径匹配时使用。

### 3.3 相关性与字段分配

先看 query 所期待的商品是否匹配：品类、用途、材质/工艺、尺寸、颜色、功能、对象和购买意图，再看热度。推荐分为极高/高/条件适用/排除，并写原因及事实依据。

高流量但错品类、竞品品牌、虚构功能和错误规格排除。准确但当前文件无 SFR 的词可用作事实描述，另标“未获本文件 ABA 支持”，不能给它借用别人的名次。

关键词主表保留完整 query；字段覆盖区分逐字完整词组、分词覆盖、语义覆盖、未覆盖。这些只是文案匹配检查，不等于已被 Amazon 索引。

### 3.4 后台 Generic Keywords

官方建议去重和补充同义表达。推荐版先使用高相关、可证实、前台未充分覆盖的有效词；用户偏好版可保留与前台重复/完整词组，必须说明空间代价与无已证实加权优势。

优先级来自 ABA SFR，不宣称后台越靠前越加权。不为接近 250 bytes 填冷僻形容词或重复品牌。字节数按最终实际 UTF-8 字符串（含空格、标点）计算；工作默认少于 250，最多 249，而不是强行凑到 250。不能截断完整词。

交付两个版本时分别写明用途、准确文本、字节数和剩余空间，不把两版拼进同一字段。去重拆词版不是一个真实的完整搜索 query。

### 3.5 美式英语与 Alexa for Shopping

以自然英文回答“是什么、适合什么、具体多大、包括什么、如何用/护理、有什么限制”。写清关系，例如某尺寸用于个人沙发休闲或床尾装饰，不暗示整床覆盖。单位、参数与结构化属性一致。

Alexa for Shopping 是原 Rufus 的后续名称。明确属性和事实问答有助于消费者理解，属于内容策略；未公开的算法、权重和排名不能当事实。不能为了被 AI 推荐编造评价、社区问答或认证。

### 3.6 完整交付包

| 内容 | 输出与约束 |
|---|---|
| Title | 品牌、核心商品词、主要区分参数；当前非媒体基线 ≤75 字符，含空格 |
| Item Highlights | 补充材料、使用场景等，当前 ≤125 字符；不是五点的替代字段 |
| 五点 | 事实→利益→具体用途/限制；自然小标题，不用 emoji/退款保证；不硬塞每个关键词 |
| Description | 自然完整纯文本主稿；只有后台支持时再提供允许的格式，不默认任意 HTML 可用 |
| Search Terms | 推荐版与按需偏好版、UTF-8 bytes 和出处 |
| 结构化属性 | material、color、size、care、included components 等按真实产品模板填写 |
| 多件促销 | 内部名称与买家展示名称分开；Buy X Save Y 需真实数量、折扣、日期、适用 SKU、叠加条件与预算支持；未知数值标草稿 |
| A+ | 模块标题/正文、图片文字、alt text、自有品牌比较表；不写竞品贬损、评论星级、限时折扣/保证 |
| FAQ / Q&A | 品牌编写，直接答事实与限制；不假扮真实买家提问，不自动发布为用户 Q&A |
| 创作者内容 | 简报、镜头、卖点、短/长广告文案与适用披露；不存在真实使用经历就不写第一人称体验 |
| 真实反馈 | 如需“5条直评”，改交 5 个真实体验采集问题；只分析真实评价，不造消费者身份、星级和使用经历 |
| 核验报告 | 字符/字节、关键词来源/布局、声明依据、图片一致性、待确认和发布状态 |

政策出处与适用范围见 [政策核验表](policy-sources.md)。不能固定套用旧的 200 字符 title、500 字符 bullet 或 2000 字符 description。

**阶段完成条件**：事实可追溯，最终选词来源和排序可复查，字段通过已知限制，图片对应售卖变体，待确认项不混入可发布稿。

## 4. 发布与复盘

制作完成不代表已上传、促销生效或平台批准。根据用户授权另行执行，记录后台结果；不因 Skill 被调用而获得发布或发消息权限。

上线后核查实际页面、变体、图序、移动端展示、是否截断、A+显示和活动条件；有后台证据再判断索引。记录流量、点击、转化、退货等口径和周期，单独追踪图片/标题改动，避免把同期所有变化归因于一个词。

更新项目记忆：已证实新事实、用户决策、版本、未决事项。通用经验与 SKU 事实分开；政策附核验日期；不把一次主观风格偏好推广到所有产品。
