按任务取用；无需每次把空表全部输出给用户。

## ABA 数据清单

source_id / file_name / sha256 / marketplace / report_type / period_start / period_end / export_filter / header_mapping / record_locator_method / missing_fields / cleaning_notes。

## 最终关键词表

| query_original | SFR_original | source_id/原始记录定位 | 站点/周期 | 相关性 | 事实依据 | 购买意图 | 字段分配 | 纳入/排除理由 |
|---|---|---|---|---|---|---|---|---|

同周期按整数 SFR 升序，保留并列；缺 SFR 另列。排除表沿用此结构。无官方数据的第三方词单独记录 source、metric、estimate_date，不填官方 SFR。

## 覆盖与声明

| query / claim | Title | Highlights | Bullets | Description | Backend | A+ / FAQ | 匹配类型或事实证据 | 状态 |
|---|---|---|---|---|---|---|---|---|

完整词组/分词/语义匹配分别标记，不能合并成“已索引”。

## 交付正文顺序

Title → Item Highlights → Bullets 1–5 → Description → Generic Keywords（准确纯文本及 bytes）→ 结构化属性 → Promotion（内部名/展示名/条款）→ A+（模块/图片字/alt text/同品牌比较）→ 品牌 FAQ → 创作者简报与文案 → 真实反馈采集 → 核验报告。

文案使用美式英语；说明/证据使用中文。可发布正文不带分析批注。待确认的稿件单独标状态，不冒充完成品。

## 五个真实体验采集方向

1. 实际在什么场景使用，尺寸或适配是否满足需要？
2. 收货后的颜色、外观、材质手感与图片是否一致？
3. 按说明使用/护理后，有什么实际变化？
4. 哪一点最有用，哪一点需要改进？
5. 买前还希望知道什么信息，有什么不适合的使用情形？

仅用于真实反馈调研，不指定好评倾向，不设置评价奖励，不替消费者写可发布直评。

## 字段检查输入

保存 UTF-8 JSON：`title`、`highlights`、`bullets`（字符串数组）、`description`、`generic_keywords`；后者是最终选用的一版字符串。使用 `scripts/check_copy.py 路径`，后台确认其他长度后可加 `--bullet-max N --description-max N`。默认只报告这些未知字段长度，不虚构统一限制。

## 交接与记忆增量

日期 / 项目与SKU / 本次确认事实与证据 / 用户决策与原因 / 最后选版与路径 / 政策核验及变化 / 未决事项与阻塞范围 / 下一步。更正错误时记录受影响的图片、文案和字段，统一修复。
