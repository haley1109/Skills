# Amazon US 商品上架

默认中文沟通、分析和交付说明；面向美国买家的文案使用自然美式英语。品牌、品类、SKU、事实和预算随项目设置，不能把 TOPWAVE 毛毯参数套到新品。

## 开始与恢复

1. 读取项目已有事实表、决策和批准版本；TOPWAVE 或“沿用毛毯经验”任务读 [项目长期记忆](references/project-memory.md)。
2. 按当前阶段读取 [上架 SOP](references/SOP.zh-CN.md) 对应段落；用 [交付模板](references/templates.md) 记录事实、图片、关键词和文案。
3. 关键政策以当次 Amazon US 官方要求及目标类目模板为准，读 [政策核验表](references/policy-sources.md)；记录核验日期、适用范围和来源。旧 Skill 的 200 字符标题等默认值不能覆盖新规则。
4. 每阶段主动提出影响决策的少量关键问题，通常一轮 3–5 项；已有答案不重问。等待信息时推进不依赖该信息的工作。缺证据的字段标“待确认”，不能写入可发布稿。

## 三阶段执行

### 一：事实、消费者和市场

- 区分自有实物图、竞品图、参考风格图；建立可追溯事实表，状态为用户确认、图像可见、推断、待核验、冲突。
- 图片不能证明材质百分比、洗护、重量、认证和性能。影棚、样板间、拍摄道具不能直接作为目标住宅和消费群体证据。
- 调研实际 Amazon US 搜索结果和相近竞品，保留 ASIN、原始图片链接/页面、访问日期、变体、价格与促销条件、评论证据；无法访问就说明缺口。美国人群、场景、价位建议标为分析判断。
- 输出产品事实表、竞品证据表、消费者定位、差异点、购买顾虑、需问问题。参数冲突只阻止依赖该参数的结论。

### 二：准确的图片与迭代

- 先给主图、副图、A+、促销素材的分镜和信息任务；确认实物锚点、允许调整项、文案依据、规格与渠道，再制作已具备输入的图片。
- 生成或编辑前实际查看全部目标参考图。可用图像工具时按其要求调用；无工具时交付可执行制作简报，不声称已经生成。
- 保留形状比例、纹理、花型、渐变方向、边缘、接缝、标签、正反面和配件数量。不能“美化”成另一种商品。竞品参考只借鉴信息结构，不复制品牌、素材或独特设计。
- 主图使用真实产品照片为基础，按类目要求制作；纯生成效果图先标为概念稿，不能自动视为合规主图。背景/光线调整也要逐项核对产品真实性。
- 每轮检查实物一致性、文案依据、尺寸比例、手部/人体错误、移动端可读性和政策；记录版本、修改点与通过/待修，保留原图和可编辑稿。

### 三：真实 ABA → 关键词 → 全套文案

- 请求真实 Amazon US ABA Search Terms 导出及站点、报告类型、日期周期、导出筛选条件。已有文件可用时不重复索要。第三方数据独立标记，不能填入官方 SFR。
- 保留源文件与 SHA-256、原文、原始记录定位、原始 SFR；同站同报告同周期先判相关性再按数值 SFR 升序。总词表也按 SFR 升序，并列保留；缺失 SFR 留空另列。跨期不混排成虚构单期榜。
- 输出原始全集/标准化表、最终相关词表、排除词表及理由、字段覆盖表。SFR 不是绝对搜索量或自然排名；筛选文件缺词不等于无人搜索。
- 用户偏好允许跨字段重复，尽量使用后台空间，但要说明官方去重建议、重复无已证实加权；默认给去重推荐版，必要时给完整词组偏好版。所有候选必须相关且有依据，不凑满。
- 使用 `scripts/check_copy.py` 检查最终 JSON 字段；Generic Keywords 按实际字符串 UTF-8 含空格计数，保守要求少于 250 bytes（最多 249），不能截断半个词。250-byte 边界和后台实际校验每次复核。
- 交付 Title、Item Highlights、五点、Description、Search Terms、结构化属性、促销名称/条款、A+ 与自有品牌产品比较表、FAQ、创作者简报/广告文案及适用披露。各字段限制依类目核实，不能把统一 500/2000 字符当通用规则。
- Alexa for Shopping（原 Rufus）的适配采用明确属性、用途、尺寸/适配、限制、洗护和直接问答；不宣称掌握未公开算法、关键词权重或保证推荐。自然可读优先于堆词。
- 不生成冒充消费者的“5条直评”、虚构体验、星级或买家 Q&A。改为 5 个真实体验采集问题/品牌文案，或保留真实来源的反馈分析；FAQ 标明品牌编写。创作者没有实际体验时只写产品介绍和拍摄提纲。

## 完成与长期维护

最终交付标明“可发布 / 待事实确认 / 待渠道审核”，列出长度、字节、词表出处、图片一致性和残留问题。只生成文件不等于上传或发布；上传、促销生效等另依用户授权执行。

每次任务结束更新项目事实/决策/未决事项与最后版本；把新教训区分为通用原则、用户偏好、SKU 事实、临时政策。只在用户要求更新 Skill 时修改全局 Skill；不把聊天中一次猜测固化为长期事实。不宣称已经写入账户级跨聊天记忆。
