# 输入、字段与执行

脚本随技能放在 `scripts/`。使用现有表格运行时的 Node（能加载 `@oai/artifact-tool`）及 Python 3.9+（含 `openpyxl`、`lxml`）。若运行时不在常规路径，可用 `KEYWORD_NODE_MODULES` 指向所用的 node_modules，用 `KEYWORD_PYTHON` 指向 Python 解释器。读取本机依赖位置后从技能的 `scripts` 目录执行下列命令。数据文件和输出文件使用项目中的路径。其他表格工具也可按相同字段和验收规则实现。

## 1. 归集原始表与西柚数据

「ABA正向查找」和「ABA反向查找」的首行应包含「搜索词」「搜索频率排名」。「竞品ASIN列表」A 列为输入 ASIN，可有表头，B 列可保留链接。若实际 ABA 导出的列名、表头位置、文本型排名或布局不同，先在工作副本中映射，再与原词和行数核对。

西柚连接在每台设备单独配置。根据该连接实际列出的工具核对参数与返回字段。在美国站用 `get_asin_variations` 核实父子关系，以 `get_parent_asin_keywords` 或月度接口逐页取得所有竞品父体检索词。核对分页、声明总量、实际条数及取数状态。优先取父体口径自然位。仅有子体数据时注明实际采用的统计方式。用 `get_keyword_info` 为三路词按批补查指标，保留每个词的报告周。接口改写原词时保留原文待核。来源周口径有差异时写清范围。

西柚记录的格式如下。数值为例，实际数据来自本次响应。

```json
{
  "marketplace": "US",
  "period": "父体反查日期范围",
  "metricsPeriod": "指标报告周",
  "competitors": [{
    "inputAsin": "DEMO000001", "parentAsin": "DEMO100001", "status": "complete",
    "rows": [{"keyword": "sample cover", "searchVolume": 100, "abaRank": 300,
              "clickConversionRate": 0.025, "organicRank": 7}]
  }],
  "keywordMetrics": [{"keyword": "sample cover", "abaRank": 300, "metricsDate": "实际报告周"}]
}
```

`complete` 表示已核对全部分页，`partial` 表示已取得部分，`pending` 表示待查询。同父体的不同输入共用一个自然位列，重复映射可用相同父 ASIN、pending 及空 rows 表示。关键词指标逐字段优先取有值的 keywordMetrics，缺项用父体反查补齐。比例用 0 至 1 的小数，缺值用 null，0 是有效的搜索量或点击转化率。

```sh
node 合并词库.mjs 原始词库.xlsx 汇总操作表.xlsx --xydc 西柚结果.json
```

省略 `--xydc` 可生成待补取的阶段版本。原表 ABA 来源之间的数据若冲突，先保留来源值和「冲突」标记，再核实原表的同周期口径。主 ABA 排名、西柚 ABA 排名和点击转化率分别判断，缺哪项就在哪项填 N。缺搜索量和缺自然位留空。需要查大量同排名时，按「排名、原词、来源、报告期」回查原始单元格或西柚响应。保留相同排名下的每一个不同原词。

## 2. 翻译与相关性

按原文精确对应中文译文。可使用 `translate_keywords` 分批翻译后审查专名、服装术语和多义词。含义仍不确定时保留原文并写中文注释。将三档判断及证据来源按[判定与复核](relevance.md)整理。

```json
{"sample cover": "示例枕套"}
```

```json
{"period": "本轮核对日期", "rows": [
  {"keyword": "sample cover", "grade": "相关", "basis": "亚马逊首页（实际观察日期，相似 8/24）"}
]}
```

如本次约定为“阈值含等号、不确定项留在分母、跨档暂取下限”，可用 `grade_counts.py` 从逐件判断的汇总生成计数行。输入为 JSON 数组，字段见 `python3 grade_counts.py --help`。把本次的百分比作为 `--strong` 和 `--related`，同时给 `--strong-count`、`--related-count` 传 `very`（仅非常相似）或 `both`（非常相似与相似之和）。另有口径时按约定计算。将计数行与初判行按原词合并，有用户现场复核时采用其结论。可把观察日期、实际比例写入 basis 供 Excel 内查阅，并在项目中保留完整计数记录。

```sh
node 筛查词库.mjs 汇总操作表.xlsx 筛查记录.json 中文翻译.json 筛查操作表.xlsx
```

## 3. 否词归因及验收

准备含 `protected`、`roots`、`rows` 的 JSON。protected 列出本项目核心词和在售变体属性。每条 root 填词根、属性类型、不匹配原因。variants 可列经核实的其他词形，contextOnly 可限定原词组合。对每条「不相关」原词给出可追溯的 roots。仅能按整词复核时填空数组、review 及 note。用 `--help` 查看可直接改写的示例。代码对强相关和相关原词检查连续词及常见英语单复数。不规则词形、其他语言和隐含意图结合实际词库人工检查。

```sh
node 否词表.mjs --help
node 否词表.mjs 筛查操作表.xlsx 逐词归因.json 完整操作表.xlsx
```

完成后按以下项目复核。

- 原三张表仍在，分步生成的「竞品反查」「待筛查词库」「词库」「否词表」都在同一个最终文件内。若输入已有用户手工页，从最近适用的版本接续，保留用户编辑。
- 搜索链接解码后与原词逐字符相同，两列在每个词前出现。用首尾空格、双空格、大小写、标点、单复数验证。有数值的 ABA 升序，同名次保持输入顺序，无排名排在最后。
- 「词库」与「待筛查词库」原词集合相同、译文及等级均填全，色标符合约定。三档合计及互斥的证据来源合计都等于总词数。初判和人工无计数复核均保留证据标签。
- 「否词表」明细逐一对应所有不相关原词，词库行号可回查。明确标出可提取词根、限原词组合及需整词复核的查询。一条原词可有多个原因，汇总词根数与原词数分别计算。
