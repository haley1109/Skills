# 亚马逊词库搭建

先看用户这次要求做到哪一步和最新的完整操作表。沿用已经核实的来源和人工修订。仅做单步时可从对应工作表开始，解释既有判断时读取已有依据即可。

1. **理解商品。** 从链接、ASIN 或图片核对商品是什么、有哪些实际在售变体，区分所给子体和父体下的其他款。先向用户说明一句话产品理解、核心词与特征词。核心词回答“买的是什么”，特征词描述材质、颜色、结构、规格、套装和用途。标出只凭图片无法确定的信息。在已安装的环境可调用 `listing-look-and-understand`，Crysevia 服装可再用 `crysevia-product-positioning`。和用户确定本项目比对范围。
2. **归集词和指标。** 读取「ABA正向查找」「ABA反向查找」「竞品ASIN列表」。通过西柚 MCP 核实竞品父 ASIN，取全分页及各父体自然位，记录站点、查询期间、报告周和完成状态。先生成「竞品反查」，再汇总三路流量词生成「待筛查词库」。按原文逐字符完全一致去重。大小写、前后或内部空格、标点、单复数均保留。主「ABA排名」优先取原表，空缺才取西柚。保留西柚原值和差异。不同词的相同排名可并存。转化指标使用「西柚点击转化率」。每行的流量词前有可点击的 SEARCH 和编码后的网址。数值排名升序，无排名置后。[数据和脚本](references/workbook.md)
3. **按搜索结果筛查。** 每个新项目开始筛查前，询问强相关和相关的百分比门槛，以及两档分别计入哪些相似商品。用户本次已给出的标准直接使用。以搜索结果内同款或可替代商品的比例优先于字面含义。逐词记录真实证据来源、页面日期或历史采集时间。把首页实查、历史自然首页、部分自然位样本、ABA 点击商品辅助初判和纯词义初判区分开。证据不足时仍给出带依据的初判。后续可凭真实商品证据复核。[判定与复核](references/relevance.md)
4. **并入「词库」。** 在完整操作表内新增工作表，保留原始数据及「待筛查词库」。每个原词后一列为「中文翻译」，每行填写「相关性」和「相关性依据」。强相关橙色、相关绿色、不相关深灰色。向用户报告各档词数，以及哪些词有逐商品计数、哪些词是初判。
5. **归纳「否词表」。** 从所有「不相关」原词中提取导致失配的最短属性词或必要短语，与实际在售变体核对，并在所有「强相关」「相关」原词中查找冲突。例如粉色睡裙对应的 `blue nightgown` 可归因为 `blue`。核心品类、兼容属性或有正向命中的词须保留必要语境。无法确认原因时留原词复核。汇总词根和每条原词归因明细同放「否词表」，附原词、词库行号、原因、例词及适用范围。整理词表的交付范围是 Excel。
6. **交付核验。** 在写出的文件中重读工作表、原词、链接、排序、原始指标、译文、档位、配色和归因计数。确认与输入的最新人工编辑一致。查验后的完整 Excel 是交付物。已有手工页需保留时，只给新页补齐格式，并提示旧页与新生成规范的差异。

需要参考一次真实项目的规模、证据覆盖和历史限制时，读[脱敏试跑复盘](references/pilot.md)。本技能没有跨项目的百分比阈值。
